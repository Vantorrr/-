# Приём заявок Qora Group

Сервис собирает публичные объявления, убирает повторы, ставит балл 0–100 и готовит короткий черновик на русском. Заявки на площадки сам не отправляет: режим по умолчанию — подтверждение. Если Telegram не настроен, дайджест пишется в файл, успешная отправка не имитируется.

В корне репозитория лежит прежний статический сайт `index.html`. Этот сервис его не меняет.

## Запуск в Docker

Нужны Docker и Docker Compose.

```bash
cp .env.example .env
docker compose up --build
```

Поднимаются API (`http://localhost:8000`), worker Celery, beat, Postgres, Redis и процесс бота. Без `TELEGRAM_BOT_TOKEN` процесс бота пишет причину в лог и завершается, сообщения не отправляет. У сервиса `bot` стоит `restart: "no"`.

Проверка:

```bash
curl -s http://localhost:8000/health
docker compose exec api python -m app.cli run
```

Ручной прогон снаружи: `POST /api/pipeline/run` (не чаще одного раза в 15 секунд). Расписание beat — `FETCH_INTERVAL_MINUTES`, по умолчанию 30, не чаще чем раз в 5 минут.

Пароль Postgres в compose (`intake`) годится только для локального стенда.

## Запуск без Docker

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
python -m app.cli run
```

Без `DATABASE_URL` используется SQLite `data/intake.sqlite`. Postgres подключается строкой `postgresql+psycopg://...`. Redis нужен для паузы, блокировки прогона и Celery. Разовый сбор и API без Redis работают: пауза тогда не сохраняется.

Тесты: `pytest`.

Бот без Docker: `python -m app.telegram.bot`. Веб-CRM: см. раздел ниже.

## Переменные

| Переменная | Зачем |
| --- | --- |
| `DATABASE_URL` | Postgres в compose, иначе SQLite |
| `REDIS_URL` | Очередь Celery, пауза, замок прогона |
| `TELEGRAM_BOT_TOKEN` | Если пусто, бот завершается и ничего не отправляет |
| `TELEGRAM_CHAT_ID` | Чат дайджеста и команд бота |
| `LLM_API_KEY` | Если пусто, черновик остаётся шаблоном |
| `LLM_BASE_URL` | Адрес OpenAI-совместимого API. Пустой адрес оставляет шаблон |
| `LLM_MODEL` | Имя модели. Пустое имя оставляет шаблон |
| `API_URL` | Адрес API для веб-CRM, по умолчанию `http://127.0.0.1:8000` |
| `FETCH_INTERVAL_MINUTES` | Период сбора beat |
| `DIGEST_HOUR_UTC` | Час ежедневной сводки, 0–23 |
| `SEND_MODE` | Принимается только `confirmation`. Другое значение игнорируется |
| `DATA_DIR` | Локальные дайджесты |
| `LOG_LEVEL` | Уровень логов |
| `HTTP_TIMEOUT_SECONDS` | Таймаут HTTP |
| `HTTP_MIN_INTERVAL_SECONDS` | Пауза между запросами к одному хосту |

Секреты только из окружения. В репозиторий их класть не нужно.

## Что делает прогон

1. Читает включённые источники из `config/sources.yaml`. Выключенные остаются ручными и в отчёт попадают как пропущенные.
2. Пишет новые карточки. Повтор того же `source_id` + `external_id` не создаёт вторую строку.
3. Сверяет длинные похожие заголовки и одинаковые URL. Совпадение помечается «дубликат», балл 0.
4. Считает балл по `config/scoring.yaml`. Неизвестное поле остаётся «неизвестно».
5. Для порога и выше готовит короткий черновик площадки и полное коммерческое предложение в Markdown, затем ставит статусы `found` → `checked` → `proposal_ready` → `awaiting_approval`. Без ключа LLM короткий черновик — шаблон, в карточке он так и подписан.
6. Пишет дайджест. В текст попадают 15 лучших по баллу, остальные остаются в базе. В ежедневную сводку входят задачи, у которых срок уже наступил.

Порог полного предложения — поле `threshold` в `config/scoring.yaml`. Сейчас это 60 баллов: тот же порог, при котором заказ считается подходящим и получает короткий черновик. Ниже порога и при причине исключения полный текст не пишется. Короткий черновик площадки не меняется. Для Profi.ru он по-прежнему не длиннее 500 знаков.

Полное предложение состоит из понимания задачи, подхода, срока и обоснования цены. В него попадают только поля `config/company_profile.yaml` и текст самого объявления. Файл профиля пустой: нет юрлица, кейсов, команды, сертификатов и контактов. Пустое поле в полном предложении пишется как «неизвестно». Короткий черновик пустое поле по-прежнему пропускает, а не заполняет выдумкой.

Статусы CRM: `found`, `checked`, `proposal_ready`, `awaiting_approval`, `sent`, `replied`, `negotiation`, `contract`, `won`, `lost`, `rejected`. Переход в `sent` требует подтверждённый результат адаптера: `confirmation.ok = true` и `external_result_id`. Кнопка «Одобрить отправку» у источника без такого API статус `sent` не ставит.

## Команды бота и веб-CRM

Команды отвечают только в `TELEGRAM_CHAT_ID`: `/start`, `/orders`, `/top`, `/stats`, `/replies`, `/settings`, `/pause`, `/resume`.

Карточка показывает название, бюджет, источник, балл, ссылку, кратко, предлагаемую цену и черновик. Кнопки: одобрить отправку, править, отклонить, открыть заказ, в CRM. Предлагаемая цена остаётся «неизвестно», пока её не заполнили отдельно. Правка черновика не ставит `sent`.

Веб-CRM, отдельно от API:

```bash
cd web
npm install
API_URL=http://127.0.0.1:8000 npm run dev
```

Список: `http://localhost:3000`. Фильтры — статус, источник, балл. Карточка: `/orders/{id}`: история статусов, срок, расходы, задачи и полное предложение, если балл не ниже порога. Счётчики на списке — сколько заказов сейчас в статусе и сколько до него дошли. «Скачать CSV» и «Скачать Excel» выгружают текущий фильтр. Заголовки колонок русские. API: `uvicorn app.main:app --port 8000`.

`GET /health` отвечает полями `api`, `database` и `redis`.

Ежедневная сводка — задача Celery beat `intake.daily_digest`, час UTC задаёт `DIGEST_HOUR_UTC` (по умолчанию 6). В текст входят задачи со сроком, который уже наступил. Если заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, сводка уходит в Telegram. Иначе она пишется в `DATA_DIR/digests/` и в лог попадает `skipped_no_credentials`. Статус заказа при этом не становится `sent`. `/pause` эту задачу пропускает.

Копия Postgres:

```bash
python -m app.backup
docker compose --profile backup run --rm backup
```

`python -m app.backup` вызывает `pg_dump` только для URL Postgres и кладёт файл в `DATA_DIR/backups/`. Для SQLite команда завершается без файла. Сервис `backup` в compose не входит в обычный `up`: его запускают отдельно. Пароль передаётся через `PGPASSWORD`, не через аргументы.

В предыдущем срезе локально прогнаны `pytest` (45 тестов) и `npm run dev` с API на SQLite. `docker compose` тогда не запускался.

## Что проверено 5 ноября 2026

- `pytest`: 33 теста, все прошли. Фикстуры в `tests/fixtures/` помечены как запись ленты или как синтетика. В прогон они не подмешиваются.
- Живой `python -m app.cli run` в 17:44–17:45 UTC, SQLite, без Telegram и без Redis:
  - FL.ru RSS, четыре категории: HTTP 200, 161 карточка.
  - Хабр Карьера, три RSS-запроса: HTTP 200, 124 карточки.
  - Каталог `https://workspace.ru/tenders/`: HTTP 200, 10 карточек, подробные страницы только у восьми открытых.
  - ЕИС, RSS расширенного поиска: три попытки, таймаут TLS-рукопожатия, 0 карточек. Фикстуры вместо ленты не подставлялись.
  - Дайджест: `data/digests/20261105T174547Z.txt`, статус `skipped_no_credentials`.
  - В базе после прогона: 295 новых, 2 дубля, 97 исключённых, 110 подходящих со статусом `awaiting_approval`. Строк со статусом `sent` нет.
- `GET /health` в тестах отвечает 200, `database: ok`, `send_mode: confirmation`.

После этого прогона фраза «от A до B» стала диапазоном, а не одной нижней границей. Повторный сетевой прогон после правки не запускался. Для коридора 100 тыс.–3 млн ₽ балл нижней границы и балл пересекающего диапазона совпадают.

Docker в этой среде не установлен, `docker compose up` не запускался. Healthcheck в compose описан, на сервере не доказан. Beat, worker и бот в этой проверке не крутились часами. Это не круглосуточный контур: нет проверенного сервера, живого расписания и внешнего наблюдения.

## Чего в этом срезе нет

Автоотклик, оплата откликов, обход капчи и вход за логином. CSV и Excel текущего фильтра есть. Новый открытый RSS добавляется блоком `kind: rss_generic` в `config/sources.yaml`. Разбор площадок — в `docs/source-matrix.md`.
