# Приём заявок Qora Group

Сервис собирает публичные объявления, убирает повторы, ставит балл 0–100 и готовит короткий черновик на русском. Заявки на площадки сам не отправляет: режим по умолчанию — подтверждение. Если Telegram не настроен, дайджест пишется в файл, успешная отправка не имитируется.

В корне репозитория лежит прежний статический сайт `index.html`. Этот сервис его не меняет.

## Запуск в Docker

Нужны Docker и Docker Compose.

```bash
cp .env.example .env
docker compose up --build
```

Поднимаются API (`http://localhost:8000`), worker Celery, beat, Postgres, Redis и процесс бота. Без `TELEGRAM_BOT_TOKEN` бот не подключается к Telegram и просто ждёт: контейнер не падает и ничего не отправляет.

Проверка:

```bash
curl -s http://localhost:8000/health
docker compose exec api python -m app.cli run
```

Ручной прогон снаружи: `POST /api/pipeline/run` (не чаще одного раза в 15 секунд). Расписание beat — `FETCH_INTERVAL_MINUTES`, по умолчанию 30, не чаще чем раз в 5 минут.

Пароль Postgres в compose (`intake`) годится только для локального стенда.

## Запуск без Docker

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
python -m app.cli run
```

Без `DATABASE_URL` используется SQLite `data/intake.sqlite`. Postgres подключается строкой `postgresql+psycopg://...`. Redis нужен для паузы, блокировки прогона и Celery. Разовый сбор и API без Redis работают: пауза тогда не сохраняется.

Тесты: `pytest`.

## Переменные

| Переменная | Зачем |
| --- | --- |
| `DATABASE_URL` | Postgres в compose, иначе SQLite |
| `REDIS_URL` | Очередь Celery, пауза, замок прогона |
| `TELEGRAM_BOT_TOKEN` | Если пусто, отправки нет |
| `TELEGRAM_CHAT_ID` | Чат дайджеста и команд `/orders`, `/top`, `/pause`, `/resume` |
| `FETCH_INTERVAL_MINUTES` | Период beat |
| `SEND_MODE` | Принимается только `confirmation`. Другое значение игнорируется |
| `DATA_DIR` | Локальные дайджесты |
| `LOG_LEVEL` | Уровень логов |
| `HTTP_TIMEOUT_SECONDS` | Таймаут HTTP |
| `HTTP_MIN_INTERVAL_SECONDS` | Пауза между запросами к одному хосту |

Секреты только из окружения. В репозиторий их класть не нужно.

## Что делает прогон

1. Читает включённые источники из `config/sources.yaml`. Выключенные остаются ручными и в отчёт попадают как пропущенные.
2. Пишет новые карточки. Повтор того же `source_id` + `external_id` не создаёт вторую строку.
3. Сверяет длинные похожие заголовки и одинаковые URL. Совпадение помечается «дубликат», балл 0.
4. Считает балл по `config/scoring.yaml`. Неизвестное поле остаётся «неизвестно».
5. Для порога и выше готовит черновик и ставит статусы `found` → `checked` → `proposal_ready` → `awaiting_approval`.
6. Пишет дайджест. В текст попадают 15 лучших по баллу, остальные остаются в базе.

Черновик берёт только заполненные поля `config/company_profile.yaml`. Файл изначально пустой: нет юрлица, кейсов, команды, сертификатов и контактов. Пока поле пустое, в текст оно не подставляется.

Статусы CRM: `found`, `checked`, `proposal_ready`, `awaiting_approval`, `sent`, `replied`, `negotiation`, `contract`, `won`, `lost`. Переход в `sent` через `POST /api/listings/{id}/transition` требует `confirmation.ok = true` и `external_result_id`. Сам сервис этот переход не делает.

Команды бота отвечают только в `TELEGRAM_CHAT_ID`.

## Что проверено 5 ноября 2026

- `pytest`: 33 теста, все прошли. Фикстуры в `tests/fixtures/` помечены как запись ленты или как синтетика. В прогон они не подмешиваются.
- Живой `python -m app.cli run` в 17:44–17:45 UTC, SQLite, без Telegram и без Redis:
  - FL.ru RSS, четыре категории: HTTP 200, 161 карточка.
  - Хабр Карьера, три RSS-запроса: HTTP 200, 124 карточки.
  - Каталог `https://workspace.ru/tenders/`: HTTP 200, 10 карточек, подробные страницы только у восьми открытых.
  - ЕИС, RSS расширенного поиска: три попытки, таймаут TLS-рукопожатия, 0 карточек. Фикстуры вместо ленты не подставлялись.
  - Дайджест: `data/digests/20261105T174547Z.txt`, статус `skipped_no_credentials`.
  - В базе после прогона: 295 новых, 2 дубля, 97 исключённых, 110 подходящих со статусом `awaiting_approval`. Строк со статусом `sent` нет.
- `GET /health` в тестах отвечает 200, `database: ok`, `send_mode: confirmation`.

После этого прогона фраза «от A до B» стала диапазоном, а не одной нижней границей. Повторный сетевой прогон после правки не запускался. Для коридора 100 тыс.–3 млн ₽ балл нижней границы и балл пересекающего диапазона совпадают.

Docker в этой среде не установлен, `docker compose up` не запускался. Healthcheck в compose описан, на сервере не доказан. Beat, worker и бот в этой проверке не крутились часами. Это не круглосуточный контур: нет проверенного сервера, живого расписания и внешнего наблюдения.

## Чего в этом срезе нет

Веб-CRM, выгрузка в Excel, автоотклик, оплата откликов, обход капчи и вход за логином. Новый открытый RSS добавляется блоком `kind: rss_generic` в `config/sources.yaml`. Разбор площадок — в `docs/source-matrix.md`.
